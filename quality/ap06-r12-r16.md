# AP-06 R12-R16: controlled native profiling capability

## Authority and scope

This is a new, independent native profiling campaign under authority `AP-06-R12-R16-native` and namespace `.quality/readiness-wave12-r16-native`. Its antecedent scientific result is the immutable AP-06 R12-R12 decision, `R12R12_FACTORIAL_CONFIRMED`, from implementation HEAD `cbaf2ac1c831e9bc98b8e568435c69bd43304334`. Historical R12-R13 and R12-R14 runs remain immutable. The R16 campaign is strictly scoped to `capability-only` and does not authorize A/B measurements under any outcome.

The campaign prepares an independent private authority, fresh DPAPI CurrentUser key custody, dedicated backend/PostgreSQL runtime, and independent freeze. It executes native capability (at most 1 Chromium) solely under an explicit, separately signed scientific authorization. No automatic A/B execution is permitted; capability PASS yields `R12R16_NATIVE_CAPABILITY_PASS` with zero formal measurement launches.

## Frozen capture contract

Use the existing `NativeTrace` for capability, one tracing session per browser, the four fixed checkpoints `baseline`, `cycle-6-close`, `idle-120s`, and `forced-GC-final`, and the existing Chromium flags (`--memlog=all`, `--memlog-stack-mode=native`, `--memlog-sampling-rate=16384`, `--memlog-keep-small-allocations`), MemoryInfra category, streaming mode, 512 MiB trace cap, 32 MiB event cap, and timeouts. Do not change trace configuration by trial and error. A dump request success or category availability does not establish effective heap profiling. The consumer confirms usable profiling only after four correlated renderer dumps contain valid `heaps_v2` allocator cohorts.

The parser accepts only the observed string GUID forms (`id` or `id2.global`) and rejects conflicts, malformed schema, PID mismatch, invalid ordering, truncation, data loss, non-finite numbers, and oversized input. Missing renderer metadata, dump coverage, or heap data is inconclusive (`R12R16_NATIVE_CAPABILITY_INCONCLUSIVE`). A metadata fallback requires a pre-registered proof joining the PID, process creation time exact, renderer role, retained Win32 handles, and the traced process across all checkpoints. Formal backend and database cleanup requires receipt verification and publication.

## Interpretation

Keep requested live allocation bytes, allocator statistics, renderer-private bytes, and reserved/committed memory separate. Report sampling and unknown allocator coverage. Aggregate snapshots do not identify individual allocation lifetimes; residual private bytes alone cannot establish a native leak. A capability PASS verifies only that the platform emits valid heaps_v2 structures for the renderer across four checkpoints, without authorizing immediate A/B profiling.

The R12-R12 trace, R13 STOP, and R14 freeze remain immutable. Public reports contain only sanitized counts, allowed categories, states, and hashes. Raw traces, stacks, paths, addresses, PIDs, and credentials stay in the private authority.
