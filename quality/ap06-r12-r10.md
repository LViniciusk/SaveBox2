## 1. Identificar a causa exata de `AP06_BROWSER_EXECUTABLE_CHANGED`

Arquivos principais:

- `frontend/tools/ap06-browser-identity.mjs`
- `frontend/tools/ap06-browser-identity.test.mjs`
- `frontend/tools/ap06-r12-r9-preflight.test.mjs`
- `tools/quality/ap06_browser_identity.py`
- `tools/quality/run_ap06_r12_r2.py`

O código atual usa:

```javascript
export function validateResolution(expected, actual) {
  check(expected && actual);
  check(
    JSON.stringify(expected) === JSON.stringify(actual),
    'AP06_BROWSER_EXECUTABLE_CHANGED'
  );
}
```

Existem dois problemas.

**Primeiro:** a igualdade de strings JSON depende da ordem das propriedades dos objetos. Se as identidades forem semanticamente iguais, mas construídas com ordem de chaves diferente, o gate pode rejeitá-las.

**Segundo:** qualquer diferença recebe `AP06_BROWSER_EXECUTABLE_CHANGED`, incluindo diferenças de configuração Playwright ou de protocolo. Além disso, `safeFailure()` converte erros desconhecidos do estágio `identity-resolution` para essa mesma classe.

Antes de alterar o comportamento, investigar qual campo realmente diverge.

### Diagnóstico sanitizado

Criar um comparador determinístico, reutilizável e sem exposição de valores sensíveis.

Exemplo conceitual:

```javascript
import { isDeepStrictEqual } from 'node:util';

export function validateResolution(expected, actual) {
  check(expected && actual, 'AP06_BROWSER_IDENTITY_MISSING');

  if (!isDeepStrictEqual(expected, actual)) {
    const error = new Error('AP06_BROWSER_IDENTITY_MISMATCH');
    error.changedFields = identifyChangedFields(expected, actual);
    throw error;
  }

  return true;
}
```

`identifyChangedFields()` deve retornar somente nomes de campos permitidos, sem valores, caminhos absolutos, argumentos completos, nomes de usuários ou tokens.

Categorias úteis:

- `executablePath`
- `executableSha256`
- `executableSize`
- `architecture`
- `productVersion`
- `chromiumVersion`
- `playwrightVersion`
- `registryDirectory`
- `installationDirectory`
- `installationFiles`
- `launchProtocol.fixedArgs`
- `launchProtocol.suffixArgs`
- `launchProtocol.profileRoot`
- `launchProtocol.allowedExperimentalArgs`

Para `installationFiles`, não publicar as chaves do objeto, pois elas podem conter caminhos absolutos. Publicar apenas `installationFiles`.

Requisitos do comparador:

- Objetos: independência da ordem das propriedades.
- Arrays: ordem estritamente preservada.
- Nenhum campo extra ou ausente aceito.
- Nenhum valor normalizado silenciosamente.
- Tipos e valores comparados integralmente.
- Diferença de executável, hash ou protocolo continua bloqueante.

Se houver divergência real de bytes ou de identidade, **não enfraquecer o gate**.

```javascript

  'AP06_BROWSER_IDENTITY_RESOLUTION_FAILED'
```

Preservar, como categorias distintas:

- `AP06_BROWSER_IDENTITY_MISMATCH`: comparação de duas identidades válidas com diferenças.
- `AP06_BROWSER_IDENTITY_RESOLUTION_FAILED`: impossibilidade de resolver a identidade real.

- `AP06_BROWSER_PROFILE_PATH_INVALID`: diretório de perfil inválido.

Adicionar as novas classes à allowlist sanitizada.

Não publicar o texto original de exceções desconhecidas.

Preservar:

```javascript
record.failureStage
record.failureClass
record.browserIdentity.failureStage
record.browserIdentity.failureClass
```

Quando houver cleanup posterior, sua falha deve ser registrada separadamente, sem sobrescrever a causa primária.

**Importante:** preservar a semântica dos recibos históricos. Alterar a classificação somente para novos fluxos; não modificar evidências R3–R9.

## 3. Criar um gate offline com o resolvedor Playwright real

Este é o requisito central da rodada.

Hoje, o fluxo científico executa:

```javascript
expected = JSON.parse(readFileSync(manifest, 'utf8'));

validateResolution(
  expected,
  await resolveBrowserIdentity()
);
```

Mas o gate offline Python verifica essencialmente o manifesto existente usando `verify_identity()`, enquanto a integração simulada injeta:

```javascript
identityResolver: async () => identity
```

Esse teste não comprova que `resolveBrowserIdentity()` real produz a identidade congelada.

### Nova validação

Criar um script Node pequeno, por exemplo:

`frontend/tools/ap06-r12-identity-preflight.mjs`

Ele deve:

1. Ler `AP06_BROWSER_IDENTITY`.
2. Executar `resolveBrowserIdentity()` real.
3. Comparar com `validateResolution()`.
4. Verificar as flags experimentais permitidas.
5. Produzir recibo sanitizado PASS/STOP.
6. Encerrar sem lançar Chromium.

Exemplo:

```javascript
import { readFileSync } from 'node:fs';
import {
  resolveBrowserIdentity,
  validateResolution,
  frozenLaunchOptions,
  AUTOPLAY_ARGS,
  NATIVE_ARGS
} from './ap06-browser-identity.mjs';

async function verifyOfflineIdentity() {
  const expected = JSON.parse(
    readFileSync(process.env.AP06_BROWSER_IDENTITY, 'utf8')
  );

  const actual = await resolveBrowserIdentity();

  validateResolution(expected, actual);

  frozenLaunchOptions(expected, AUTOPLAY_ARGS);
  frozenLaunchOptions(expected, [...AUTOPLAY_ARGS, ...NATIVE_ARGS]);

  return { status: 'PASS' };
}
```

Adaptar à interface real e ao contrato de publicação existente.

Não imprimir `expected`, `actual`, argv completos ou caminhos.

Em caso de erro, emitir classe e campos divergentes sanitizados, com saída e exit code coerentes.

### Ambiente de execução

O gate deve executar com:

- O mesmo executável Node.
- O mesmo `cwd=frontend`.
- O mesmo `AP06_BROWSER_IDENTITY`.
- O mesmo `AP06_BROWSER_TEMP_ROOT`.
- Os mesmos `TEMP` e `TMP`.
- O mesmo helper Python.
- A mesma instalação `playwright-core` / `@playwright/test`.
- As mesmas flags e resolução do headless shell utilizadas no preflight real.

Construir esse ambiente através de `environment()` existente, não por um segundo conjunto de variáveis montado manualmente.

**Não basta rodar `resolveBrowserIdentity()` em um processo de teste com ambiente diferente.**

O gate deve passar na mesma configuração usada por `tools/ap06-r12-r2-preflight.mjs`.

O recibo precisa registrar HEAD, identidade do manifesto por hash, status, versão Playwright/Chromium permitida e orçamento científico zero, sem dados privados.
