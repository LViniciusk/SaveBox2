## STOP: defeito no validador experimental

`run_ap06_integration_probe.py::validate_condition()` calculou o número de SourceBuffers integrados como `cycle * sum(len(fixture['tracks']))`. Para o corpus A/V, vídeo, A/V isso exigia **5 por ciclo / 30 no sexto close**.

O contrato real é outro: `stream-transmux-ready.ts::handleTransmuxReady()` monta `combinedCodec` e publica **um item de initData, id 0**, usando o init segment multiplexado do MP4Box. `VideoStreamService` cria um SourceBuffer por item de **initData**, não por track do manifesto MP4. R7.1 observou corretamente **3 criados/3 liberados por ciclo, 18/18 no final**. Primeiro mismatch: cycle-1-close, 3 observados versus 5 esperados. Todos os demais contadores de lifecycle conferidos ficaram balanceados.

Os testes Python de política tinham uma track por fixture; as checagens Angular validaram playback A/V e ownership balanceado, sem aplicar esse cálculo Python ao corpus real. Essa lacuna explica por que os gates passaram antes do freeze. É um defeito desta revisão do validador, registrado para revisão.

As fontes, plano e fixtures congeladas foram preservados. Nenhum threshold/contador/raw foi corrigido após medir, nenhum resultado foi promovido retrospectivamente a PASS, nenhum browser foi repetido. Corrigir essa expectativa e adicionar regressão com initData multiplexado exige **uma nova revisão e campanha congelada**, começando pelo controle e R7.1. Não avançar diretamente a R7.2 com estes raws.
